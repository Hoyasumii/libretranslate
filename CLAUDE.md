# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

`@hoyasumii/libretranslate` — an unofficial TypeScript SDK for the LibreTranslate HTTP API (generated by orval
from our own OpenAPI spec), an MCP server over it (stdio and Streamable HTTP) and a CLI that is an MCP client.
Node >= 20, CommonJS through `tsc`, pnpm. It mirrors `@hoyasumii/signoz` (`../signoz`), which mirrors
`@hoyasumii/plane` (`../plane`): the MCP/CLI layers were ported from there and follow their design, Windows support
included.

**License boundary.** This package is MIT. LibreTranslate and its official MCP server are AGPL-3.0: never read,
copy, port or depend on their code. `spec/openapi.yml` describes the API from its public documentation
(docs.libretranslate.com) and from black-box answers of a running instance only.

## Common Commands

```bash
pnpm install              # Install dependencies (and the husky hooks)
pnpm build                # tsc → dist/
pnpm test:unit            # Jest unit tests (a fake LibreTranslate on node:http; no network)
pnpm test tests/unit/mcp/tools.test.ts   # One file
pnpm test:live            # Against a real instance, from .env.test (see env.example)
pnpm check:types          # tsc --noEmit over src, tests and scripts
pnpm check:lint           # oxlint
pnpm check:format         # oxfmt (120 columns)
pnpm check:knip           # Unused files, exports and dependencies
pnpm codegen              # spec → src/generated/ (orval) + src/mcp/generated/catalog.json (never hand-edit)
pnpm codegen:mcp          # Only the MCP catalog
pnpm docs:dev             # Preview the docs site (append `--locale pt-BR`)
pnpm docs:build           # Build the docs site, every locale, into website/build/
pnpm docs:serve           # Serve website/build/ (where search works; it does not under docs:dev)
GIT_USER=<user> pnpm docs:deploy  # Build and push the site to the gh-pages branch (GitHub Pages)
```

Husky runs lint and format on commit, types, knip and unit tests on push. Commits follow
Conventional Commits (commitlint). Every script must run on Windows too: no `rm`, `$VAR`, `VAR=1 cmd`.
`.github/workflows/cd.yml` (Continuous Delivery) runs on every push to `main`: the same checks and the build, then
`npm publish` (Trusted Publishing, no token) plus a `v<version>` tag and GitHub release when `package.json`'s version
is not on npm yet, and `pnpm docs:deploy` to `gh-pages` when the push touches `website/` or `src/`. To release, bump
`version` and merge to `main`.

## Architecture

**SDK** (`src/`). `orval.config.ts` reads `spec/openapi.yml` (OpenAPI 3.1, with our operationIds) and writes
`src/generated/`: `endpoints.ts` (one `fetch` function per operation, `client: "fetch"`,
`includeHttpResponseReturnType: false`), `model/` (types) and `zod.ts` (request/response zod schemas).
Every generated function sends through the mutator `customFetch` (`src/transport.ts`), which takes the client's
`TransportConfig` (base URL, timeout, fetch, secrets) from the `transport` field the client puts in each call's
`RequestInit`, parses JSON and throws `LibreTranslateApiError` (`src/errors.ts`, `{ error }` bodies, `redact`
masks the key). `createLibreTranslateClient` (`src/client.ts`) wraps the generated functions: `source` defaults to
`auto`, the API key is added to the body of keyed operations (`api_key` is a body field, not a header),
`translateFile` turns a Blob into a named `File` (the instance picks the format by extension), `downloadFile`
fetches the `translatedFileUrl`, and `call(operationId, body)` serves the generic MCP tools.

**MCP server** (`src/mcp/`, the `@hoyasumii/libretranslate/mcp` subpath). `buildLibreTranslateMcpServer(client)`
(`build.ts`) registers the tools; `serveLibreTranslateMcpStdio` (`stdio.ts`) and `startLibreTranslateMcpServer`
(`server.ts`, stateless HTTP on 127.0.0.1, Host check, `/health`, token-guarded `POST /shutdown`) serve it.
`cli.ts` is the `libretranslate-mcp` bin — in stdio mode stdout is the protocol, log to stderr. `config.ts`
resolves flag > env > saved `.env` > default (`LIBRETRANSLATE_URL` default `http://localhost:5000`, optional
`LIBRETRANSLATE_API_KEY`, `PORT` default 3768).

- `tools/translate.ts`: curated tools (translate, translate_file, detect, languages, status, suggest); their
  inputs are orval's zod schemas minus `api_key`. `translate_file` reads a local path and never overwrites without
  `overwrite: true`.
- `tools/generic.ts`: `libretranslate_resources`/`_describe`/`_call` over `generated/catalog.json`, built from the
  spec by `scripts/build-mcp-catalog.ts` (file upload left out, `api_key` stripped). `invoke.ts` refuses unknown
  body fields, `api_key`, and writes (`suggest`) without `confirm: true`. `tests/unit/mcp/catalog.test.ts` fails
  when the catalog is stale.

**CLI** (`src/cli/`, the `libretranslate` bin, citty 0.1.x). `connect.ts` connects over HTTP with `--url` or
in-process through `InMemoryTransport`; `run.ts` turns each tool into a subcommand (`schema-args.ts` maps JSON
Schema to flags). `libretranslate mcp …` (`src/cli/mcp/`) is plane's code: `config` (prompt, flags or `--web`
form; `config-ui.ts` holds the rules — a blank key keeps the saved one, `-` clears it), `start`/`stop`/`status`
(`daemon.ts`), `boot` (`boot.ts`), `install`/`uninstall` (`install.ts`, `hosts.ts` with the WSL→Windows bridge).
Every OS call goes through `McpDeps` (`deps.ts`, on `cross-spawn`). `requireSavedConfig` refuses every command but
`mcp config`, `mcp uninstall` and help until a URL is saved.

`libretranslate service up|down|status|logs` (`src/cli/service.ts`) runs LibreTranslate in a Docker container
(`libretranslate`, published on 127.0.0.1, models in the `libretranslate-models` volume). It shows in the root usage
only when `docker --version` succeeds (probed only when rendering usage), every subcommand checks that Docker is
installed and its daemon answers, it needs no saved configuration, and `up` saves the local URL when none is saved.
Its Docker calls go through `ServiceDeps` (`exec`/`spawn` from `McpDeps`, plus `fetch` and `sleep`).

`boot.ts`, `daemon.ts`, `deps.ts`, `hosts.ts`, `index.ts`, `install.ts` and `picker.ts` track plane's versions:
re-derive them from `../plane/src/cli/mcp/` by renaming and re-applying the edits rather than diverging by hand.

**Docs site** (`website/`, a pnpm workspace package, plane's site with a teal accent, #14a394): Docusaurus,
published to GitHub Pages at `https://hoyasumii.github.io/libretranslate/` by `pnpm docs:deploy`. The guides are
plain Markdown in `website/docs/`, mirrored page for page in
`website/i18n/pt-BR/docusaurus-plugin-content-docs/current/`; change both together (`tests/unit/website.test.ts`).
`website/docs/api/` is generated by docusaurus-plugin-typedoc on the `en` build only, and gitignored.
`llms.txt` and `llms-full.txt` are generated into the build root by docusaurus-plugin-llms; never hand-write them.

## Conventions

- Code, comments and messages in English.
- Avoid `any`; tool inputs are zod schemas (orval's where they fit), API shapes come from `src/generated/model`.
- Never log the API key; tool errors go through `describeError` (`src/mcp/errors.ts`).
